## 1. Why v2 is worth building at all

v1 did not fail diffusely. It failed in a specific, observable, **already-
instrumented** place: the seconds right after a pitch or run, when the fair
value has moved and the counterparty saw it before our anchor did.

Two facts make this a real opportunity rather than wishful thinking:

1. **The loss is localised.** −8.78¢ inside the ±15s window vs −0.96¢ outside
   it. The outside-window number is *near break-even after the +4.08¢ spread*.
   If v2 simply stops losing money in the window, the strategy plausibly turns
   non-negative — without needing any forecasting edge.
2. **The signal already exists in the pod.** `live_maker_pod.py` already tracks
   `state_changed_at` (when a state change was observed) and stamps every fill
   with `secs_since_state_change`. v2's core mechanic is a gate on a value the
   code already computes. This is a small, low-risk change, not a rebuild.

This is the disciplined next step: not "quote better" (vague), but "stop
quoting when we know we are stale" (specific, measurable, cheap).

## 2. The mechanism

**When an observed game-state change is < T seconds old, do not rest quotes
(or rest them materially wider).** After T seconds, resume normal quoting.

- Route A — **suppress**: pull both sides for T seconds after each state change.
  Zero fills in the window → zero pick-off. Cost: forgone spread on any
  *uninformed* flow that would have arrived in the window.
- Route B — **widen**: keep quoting but at a much larger offset for T seconds,
  so only trades that move far enough to still be profitable-after-adverse-
  selection get filled. Softer, keeps some spread, harder to size.

v1's own tape already ran two Tier-2 arms in this family
(`postevent_suppress_15s`, `postevent_widen_30s`); neither cleared zero on 9
games, but both were *offline replays of v1's quotes*, not a live v2. The point
of v2 is to run the mechanism live and gather a clean sample.

## 3. What "state change" must mean — the load-bearing risk

v1 measured the pick-off against **observed** state changes
(`state_changed_at` = when the maker's own poll saw the change). But the pick-off
is by definition driven by counterparties who saw it *earlier*. So:

- If `state_changed_at` lags true first-pitch/score by even a few seconds, the
  suppression window is **already too late** — the informed flow has landed
  before the timer starts. v2's first task is to **measure the lag between true
  event time and `state_changed_at`**, and if it is large, the fix is faster
  state polling, not a wider suppression window.
- This is the single most likely way v2 fails, and it must be measured *before*
  trusting any suppression result. A suppression window anchored to a stale
  observation defends the wrong seconds.

## 4. Evaluation plan — and a hard constraint from v1

**Constraint (Lesson L5):** the paper tape only records fills that crossed the
maker's quotes. Tier 2's offline replay can therefore evaluate arms that fill on
a **subset** of v1's fills — i.e. *wider or suppressed* arms — but NOT arms that
would have filled where v1 didn't. Suppress and widen are exactly the measurable
direction, so offline replay is valid for the pre-live sizing. Tightening is not
evaluable this way and is out of scope.

Phased, mirroring v1's discipline:

1. **Offline (no deployment):** using `src/maker_challenger.py`, replay v1's tape
   under suppress-T and widen-T for a grid of T ∈ {5, 10, 15, 20, 30}s. Pick the
   T that maximises markout net of forgone spread. This is free and uses data we
   already have. Report the lag measurement from §3 alongside.
2. **Live paper pilot:** deploy v2 as its own arm (the `betting-live-maker` unit
   is idle and available — repurpose it, keep v1's kill file logic). Shadow-quote
   v1's old logic in parallel as the control, so v2-vs-v1 is measured on the same
   tape rather than across different slates.
3. **Gate:** pre-register BEFORE the pilot (see §5).

## 5. Pre-registered gate (fill in the blanks BEFORE deploying)

Same shape as v1, so we cannot rationalise a marginal result:

- **Primary:** fee-adjusted +5m markout **> 0** over **≥ N fills**
  (N to be set from a power calc on v1's per-fill sd of 11.54¢ — v1 needed ~500
  for ~1.4¢ resolution; set N for the effect size v2 must beat).
- **Robustness:** robust to excluding the single best day (v1's clause; it
  earned its keep).
- **Head-to-head:** v2 markout must beat the *contemporaneous* v1 shadow markout
  by a pre-registered margin — not just clear zero, but actually improve on the
  thing it replaces. (This is the margin the RECURSIVE_REVIEW_DESIGN doc never
  specified; specify it here.)
- **Anti-cannibalisation:** confirm suppression does not simply move the losses
  — check that outside-window markout stays ≥ its v1 level (suppressing the
  window must not push flow into worse fills elsewhere).
- **Else:** kill, exactly as v1.

## 6. Explicitly NOT in scope

- **No forecasting edge.** v2 does not try to predict state changes or price
  better than the market. It only declines to quote when it knows it is stale.
  If that alone doesn't clear the gate, the honest conclusion is that
  market-anchored MLB making does not work here, and we stop — we do not bolt on
  a fair-value model to rescue it (that is a different pod, not v2).
- **No tighter quoting** (unmeasurable on the existing tape, L5).
- **No parameter search beyond the single T grid** — one coarse,
  theory-motivated grid, per the anti-rule-search rule. T is chosen for a
  *reason* (the measured window), not swept for the best backtest number.
- **No auto-apply / self-tuning.** v2 is a fixed hypothesis with a fixed T.
  The Tier 3 auto-adjustment layer stays unbuilt and its three open design gaps
  (no [min,max] bounds, no promotion margin, arm-budget arithmetic) are
  unresolved — do not build on them.

## 7. Open questions to resolve early

1. **The lag in §3** — measure first; it can invalidate the whole approach.
2. **Suppress vs widen** — offline grid decides; do not pre-commit.
3. **Inventory during suppression** — v1 held inventory through settlement. If
   v2 suppresses mid-game while holding a lopsided book, does it want to keep
   one side quoting to flatten? (Probably yes on the *reducing* side only.)
4. **First-night anchor contamination** (v1 L6) — v2's restart path needs the
   same anchor-reset guard or it manufactures phantom fills.

## 8. First concrete step

Run the offline suppress/widen grid on v1's existing tape and produce the §3 lag
measurement. Both use data already on disk and the `maker_challenger` harness
already built — no deployment, no new data, no risk to anything. That result
decides whether v2 is worth a live pilot at all.
