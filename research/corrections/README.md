# `research/corrections/` — audit records for mis-booked settlements

Committed copies of correction files generated against the droplet's live trade
history. The generators never mutate trade history; they write a new file and print
a P&L delta, and **applying a correction to the live books is a separate, deliberate
decision.** These copies exist because the droplet's `data/` is gitignored, so the
audit trail would otherwise live only on the VPS.

## `P-017_scalar_corrections_20260726.jsonl`

One row: `KXPGATOP20-3MO26-JDAY`.

Generated by `scripts/backfill_golf_scalar_corrections.py` on 2026-07-26 after the
scalar settler fix was deployed. The row was booked `VOID / kalshi_withdrawn` at
$0.00 by the pre-fix settler; the market actually settled `result="scalar"` with
`settlement_value_dollars = 0.24` — a **partial payout, not a refund**.

| | booked | corrected |
|---|---|---|
| outcome | VOID | **WIN** |
| gross P&L | $0.00 | +$0.43 |
| fees | $0.5332 | $0.5332 |
| **net P&L** | **−$0.53** | **−$0.10** |

**Delta +$0.43**, and the row moves from excluded (VOID) to counted in the gate
sample. Total P-017 P&L moves −$171.63 → −$171.20.

`corrected_outcome = WIN` with a negative net P&L is deliberate, not a sign error:
the outcome records whether the contract paid more than it cost (0.24 > 0.23 fill),
while P&L is booked net of fees per the house convention. A 99¢ binary that resolves
YES has the same shape.

**Scope check:** this is the *only* row with the buggy signature
(`resolution_source="kalshi_withdrawn"` and no `settlement_kind`) across the active
log and all nine archives. There is no wider backlog.

**Status: NOT applied to the live trade log.** The live row still reads VOID. At
$0.43 on a tournament that is not yet fully settled, applying it is optional; if it
is applied, do it while the service is stopped and record it here.
