# TASK 1 — Fit the leg correlation ρ (CRITICAL PATH)

**Why this is first.** Gate 0 for P-029 is specified as *"in-zone median margin ≥ +2.0¢ against a
**correlation-adjusted** price"*, and the decision is due 2026-08-04. The copula that supplies that
adjusted price (`src/combo_copula.py`) currently ships **priors, not measurements**:
`same_player 0.35 · same_game 0.18 · same_day 0.02`. On live data those priors imply a **+5.32¢**
correction on same-player combos — **1.7× the entire +3.17¢ measured edge.** A number that large
resting on a guess is a sensitivity, not a finding. Fit it.

**The fitter is already built and tested** (`combo_research/fit_correlation.py`, 16 tests). It has
never produced an identified result, for one reason: pulling combos from the API returns only the
newest slate, so `n_days = 1` and ρ is confounded with that day's outcome rate. It correctly refuses
to present that as a result. **The VPS archive spans multiple days and is the input it needs.**

```bash
ssh root@143.198.162.120
cd /opt/p029 && git fetch origin && git reset --hard origin/main
./venv/bin/pip install --quiet numpy          # if the box predates the numpy addition
./venv/bin/python3 combo_research/archive_settled_combos.py \
    --out /var/lib/p029/archive --report      # how many days does the archive span?
./venv/bin/python3 combo_research/fit_correlation.py \
    --archive /var/lib/p029/archive \
    --out combo_research/fitted_rho.json \
    --max-combos 200000
```

**Acceptance:**
- Every block you intend to use reports `identified: true` with `n_days ≥ 3` and a `ci95`.
- `same_player` will probably fall under the 30-pair floor — it was 11 pairs on a day's API sample.
  **Leave it unfitted and keep the prior.** `load_rho()` does that automatically. Do not invent a
  value, and do not let it silently become 0.
- If the archive spans fewer than 3 days, **stop and report that** rather than shipping a
  single-slate fit. Waiting a few days is correct; a confounded ρ is not.

**Then:** commit `fitted_rho.json`, and point the pricer at it — `shadow_public.py` should build its
copula with `ComboCopula(rho=load_rho("combo_research/fitted_rho.json"))` rather than the bare
default. Add a test asserting the file loads and that an unfitted block retains its prior.

**Report:** fitted ρ per block with CIs, and — the decision-relevant number — **how much the Gate 0
in-zone margin moves** between prior-ρ and fitted-ρ. If fitted ρ is materially higher than the
priors (the confounded single-day run suggested `same_day +0.355`, `same_game +0.688`), the Gate 0
correction grows and the margin shrinks. Say so plainly.

### The trap that will bite you if you re-derive this
**A SETTLED COMBO CAN HAVE UNSETTLED LEGS.** A combo resolves NO the moment any one leg fails, so
the remaining legs never resolve — 43 of 60 legs sampled from settled combos were still `active`.
Keeping only the resolved legs selects exactly the legs that *decided* the outcome and biases ρ
upward without limit. The fitter already requires **every** leg of a combo to have settled. Do not
"optimise" that away.
